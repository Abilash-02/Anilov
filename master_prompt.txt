  7. CI BUILD PIPELINE
  Create .github/workflows/build-apk.yml .

  Triggers: push to main , and workflow_dispatch .

  Steps (ubuntu-latest):

   1. Check out the repository.
   2. Set up Java 17 (Temurin) and stable Flutter with subosito/flutter-action (with
      caching).
   3. If android/ is missing: run flutter create --platforms=android --org com.anilov
        --project-name anilov in a temporary directory and copy only its android/ folder
        into the repository. Never let it overwrite lib/ , pubspec.yaml , or test/ .
   4. python3 -m pip install pillow , then python3 tools/make_icon.py .
   5. python3 tools/patch_android.py . This script must be idempotent and must: set the
        app label to 'Anilov', add the INTERNET permission, add the POST_NOTIFICATIONS
        permission, and keep cleartext traffic disabled.
   6. flutter pub get .
   7. dart run flutter_launcher_icons and dart run flutter_native_splash:create .
   8. dart format . (apply formatting in the runner so it never fails the build on style
        alone).
   9. flutter analyze .
 10. flutter test .
 11. flutter build apk --debug .
 12. Print the APK size and upload build/app/outputs/flutter-apk/app-debug.apk as an
        artifact named anilov-debug-apk .

  Do not make analyze or test non-blocking to hide errors. Fix them.

  If a plugin needs extra Android configuration (for example core library desugaring for
  notifications), add that in tools/patch_android.py and explain it.

  8. FEATURES

  Navigation
  Bottom bar with five tabs: Home, Explore, Schedule, Watchlist, Profile. Profile contains
  Watch History, Settings, and About/Attribution. Preserve tab state and support Android
  back navigation.


  Metadata provider
        Primary provider: AniList GraphQL ( https://graphql.anilist.co , public data needs
        no key). Check its current official docs for rate limits, terms, and attribution.
        Put it behind a provider abstraction. Keep the API client separate from widgets.
        Handle nulls, timeouts, HTTP errors, and rate limits (HTTP 429, respect Retry-After ).
        Cache suitable responses and avoid duplicate requests.
        If the API is unavailable, show a retry state. Never show fabricated data.
        Provide JSON fixtures for tests.


  Home
  Featured carousel, Airing today, Trending, Popular, Top rated, Currently airing, Continue
  watching, Recently viewed, genre shortcuts, search entry point. Use real data only.
  Include skeleton loaders, retry buttons, and empty states. A poster tap opens Details.


  Schedule (core feature)
        Use AniList airing schedules for today and a weekly view with one tab per weekday.
        Convert times to the device's local time zone. Show episode number, time, cover, and
        title.
        Filter: All, or My watchlist only.
        Label times as original broadcast times. They do not imply availability on any service or
        region.
        Daily notification (Run 5): the user chooses a time in Settings. Once a day, summarize
        watchlist shows airing that day. Use workmanager and local notifications. Request
         POST_NOTIFICATIONS at runtime on Android 13+ with an explanation, and degrade
        gracefully if denied. Document that background timing is not exact. Allow a per-show
        reminder toggle.

  Explore and search
  Debounced title search, pagination, filters (genre, format, status, year), sort (popularity,
  rating, newest), search history with a clear button, no-results and error states.


  Anime details
  Cover and banner, titles and alternates, synopsis, genres, year, format, episode count,
  status, studio, average score with source, related anime if supported, trailer (when
  provided), Where to watch buttons, watchlist controls, watched-episode counter,
  continue action, and an episode list when reliable episode metadata exists. Keep episode
  metadata clearly separate from playable sources.


  Optional episode enrichment: ani.zip
        Endpoint: https://api.ani.zip/mappings?anilist_id=<id> .
        Use it only for episode titles, thumbnails, air dates, and runtime, behind the provider
        abstraction. AniList stays the primary source.
        Never use it for video or streaming links.
        It is an unofficial community service. Parse every field as nullable, cache responses,
        and if it fails, times out, or returns nothing, fall back to plain episode numbers. The app
        must never crash or show fake data.
        Add a mocked-response unit test and an attribution line in About.


  Watchlist and progress
  Statuses: Planning, Watching, Completed, On hold, Dropped. Add and remove (removal
  needs confirmation), change status, update watched-episode count and last-watched
  episode, filter and sort. Persist locally with sqflite so data survives restarts. Prevent
  duplicates. Handle unknown episode totals and invalid values safely. Everything works
  without any account.


  Watching

   1. Official 'Where to watch' links from AniList data, opened with url_launcher . Show
        only links the API returns. Never construct or guess links.
   2. Official trailers via youtube_player_iframe , following the platform's terms.
